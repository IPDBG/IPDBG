# IPDBG demo for the Digilent Cmod S7

The same demo design as the [co-simulation](../../../sw/CoSim/README.md),
running on a [Digilent Cmod S7](https://digilent.com/reference/programmable-logic/cmod-s7/start)
(AMD Spartan-7 XC7S25). OpenOCD talks to the FPGA through the JTAG adapter
on the board, everything above that is the same as in the co-simulation:
the four cores are on the same ports, and the examples from the
[CoSim README](../../../sw/CoSim/README.md#trying-the-tools) work unchanged.

Part of [IPDBG](https://github.com/IPDBG/IPDBG).

## Requirements

* Digilent Cmod S7
* Vivado, tested with 2023.2. The free Standard edition supports the XC7S25.
* OpenOCD 1.0.0 or later, or OpenOCD from git including commit 52ea420
  (*ipdbg: simplify command chains*), with the IPDBG server
* The host tools you want to try, see the
  [CoSim README](../../../sw/CoSim/README.md#the-demo-design)

## Building

```sh
cd rtl/demo/cmod-s7
vivado -mode batch -source build.tcl
```

`build.tcl` creates the Vivado project in `build/`, builds it and copies the
bitstream to `top.bit`. At the end it prints the worst setup and hold slack;
the full timing report is `build/timing_summary.rpt`. The project in
`build/cmod-s7.xpr` can also be opened in the Vivado GUI.

## Loading and starting

Connect the Cmod S7 via USB, then:

```sh
cd rtl/demo/cmod-s7
openocd -f demo.cfg
```

`demo.cfg` loads `top.bit` into the FPGA and starts the IPDBG server on the
ports 4242 to 4245. The bitstream is only loaded into the FPGA, not into
the flash, so the board forgets it when it is powered off.

On Windows, OpenOCD needs the libusbK driver for the board's FTDI chip
(interface 0). Install it with [Zadig](https://zadig.akeo.ie): enable
*Options → List All Devices*, select the entry of the board ending in
*(Interface 0)* and choose *libusbK*. Leave interface 1 alone.

## The demo design

The demo design ([`top.vhd`](top.vhd)) connects four IPDBG cores to the
JTAG hub:

| Port | Core               | Configuration |
|------|--------------------|---------------|
| 4242 | Logic Analyzer     | 16 channels, 512 samples, sampling every clock cycle |
| 4243 | Waveform Generator | 16 bit, 4096 samples, no double buffer |
| 4244 | IoProbe            | 4 outputs, 10 inputs, used with IoView |
| 4245 | BusAccess          | Wishbone master (`WbMaster`), 16 bit address, 32 bit data, 2 bit `sel` |

The system clock of 100 MHz is generated by an MMCM from the 12 MHz board
clock. This is also the sample rate of the Logic Analyzer and of the
Waveform Generator. PulseView shows sample numbers instead of times, because
the Logic Analyzer does not report its sample rate.

The cores are connected to each other and to the board:

* The Logic Analyzer records the output of the Waveform Generator, as in the
  co-simulation.
* The IoProbe outputs drive the four LEDs.
* Behind the Wishbone master is a single 32 bit register, which answers at
  every address. Each `sel` bit selects 16 bits of it.
* IoProbe inputs 7..0 show bits 7..0 of this register, so a write with
  BusAccess shows up in IoView. After the
  [BusAccess example](../../../sw/CoSim/README.md#busaccess), which writes
  `0xcafebabe`, IoView shows `0xbe` there.
* IoProbe inputs 9..8 show the two buttons.

Differences to the co-simulation: more sample memory in the Waveform
Generator, IoProbe on the LEDs, buttons and the register instead of a
loopback, writes to the register are not printed anywhere, and a second
IoProbe on the UART (see below).

## A second IoProbe on the UART

The design also connects a second IoProbe to the USB UART of the board
(FTDI interface 1), through the UART transport
[`IpdbgUart`](../../Uart) instead of the JTAG hub:

| | |
|-|-|
| Baudrate | 115200 (115741 exactly: 100 MHz / (16 × 54)), 8N1 |
| IoProbe | 8 outputs, 10 inputs: inputs 9..8 show the two buttons, inputs 7..0 the outputs |

On the host, [UartBridge](../../../sw/UartBridge/README.md) forwards a TCP
port to the serial port. It runs independently of OpenOCD, both can be used
at the same time:

```sh
UartBridge --list                        # find the port of the board
UartBridge /dev/ttyUSB1 115200 4246      # Linux, usually the second ttyUSB of the board
UartBridge COM5 115200 4246              # Windows, the COM port of interface 1
```

Then connect IoView to `127.0.0.1` port `4246`: every output you set shows
up at the inputs 7..0, the buttons at 9..8. The BusAccess library works
the same way, e.g. from Python:

```python
import BusAccess

ba = BusAccess.IpdbgBusAccess()
ba.open("127.0.0.1", "4246")
print(ba.getCoreType(), ba.getReadDataSize(), ba.getWriteDataSize())  # 1 10 8
ba.write(0, 0xa5)
print(hex(ba.read(0)))    # 0xa5, plus 0x100/0x200 while a button is pressed
ba.close()
```

## Files

| File          | Content |
|---------------|---------|
| `top.vhd`     | Demo design: MMCM, JTAG hub and the four IPDBG cores, IoProbe on the UART |
