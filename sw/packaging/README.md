# Packaging and releases

For the maintainers: how a release is made, and how the Windows ZIP and the
Linux packages are built and tested. Users find the installation in the
[top-level README](../../README.md#installation) and in
[`sw/README.md`](../README.md).

| Directory | Contents |
|-----------|----------|
| [`windows/`](windows) | the Windows ZIP: `make-zip.sh` and the `README.txt` in the ZIP |
| [`obs/`](obs/README.md) | the Linux packages for the openSUSE Build Service, and scripts to build and check them in containers |
| [`aur/`](aur/README.md) | the `PKGBUILD` of the Arch Linux packages, built on OBS |
| [`pypi/`](pypi/README.md) | the description of the Python package on PyPI; the build files are [`sw/pyproject.toml`](../pyproject.toml) and [`sw/setup.py`](../setup.py) |

## Continuous integration

The workflow *Host software* ([`.github/workflows/sw.yml`](../../.github/workflows/sw.yml))
runs on every change of `sw/`:

| Job | What it does |
|-----|--------------|
| `linux` | builds everything on Ubuntu, loads the Python and Octave modules, checks `make install` and `make uninstall` |
| `linux-packages` | builds the packages of [`obs/`](obs/README.md) and [`aur/`](aur/README.md) in containers of Fedora, openSUSE, Debian, Ubuntu and Arch, installs and checks them; the packages are attached to the run |
| `windows-zip` | builds the Windows ZIP with MSYS2 (UCRT64), starts UartBridge with only the DLLs of the ZIP; the ZIP is attached to the run |
| `windows-bindings` | builds the Python and Octave bindings with MSYS2 and loads them; they are not in the ZIP |
| `python-wheels`, `python-sdist` | build the Python package `ipdbg` for Linux, Windows and macOS with [cibuildwheel](https://cibuildwheel.pypa.io), and the source archive; each wheel is imported in a test |
| `release` | only for a tag `v*` and if all other jobs passed: creates a draft release on GitHub with the ZIP |
| `pypi` | only for a tag `v*`, after `release`: uploads the Python package to PyPI |

## Release

1. Set the version in [`sw/VERSION`](../VERSION), in the files of
   [`obs/`](obs/README.md#new-version) and in [`aur/PKGBUILD`](aur/README.md#release),
   rename *Unreleased* in [`CHANGELOG.md`](../../CHANGELOG.md) to the version
   and date, commit and push. The job
   `linux-packages` checks that the versions match.
2. Tag the commit and push the tag:

   ```sh
   git tag -a v0.1.0 -m "IPDBG 0.1.0"
   git push origin v0.1.0
   ```

   The tag has to match `sw/VERSION`, else the job `windows-zip` fails.
3. When all jobs passed, the draft release is on the
   [releases page](https://github.com/IPDBG/IPDBG/releases). Write the
   release notes from the changelog – the notes generated by GitHub only
   list the commits – and publish the release.
4. Update the Linux packages on OBS, see [`obs/README.md`](obs/README.md#new-version).
   The job `pypi` has already uploaded the Python package.

## PyPI

The job `pypi` uploads without a password ([trusted publishing](https://docs.pypi.org/trusted-publishers/)).
Once:

1. On [pypi.org](https://pypi.org), with an account with two-factor
   authentication: *Publishing* → *Add a new pending publisher*, project
   `ipdbg`, owner `IPDBG`, repository `IPDBG`, workflow `sw.yml`,
   environment `pypi`.
2. On GitHub: *Settings* → *Environments* → *New environment* `pypi`.

## Windows ZIP

[`windows/make-zip.sh`](windows/make-zip.sh) builds the host software in an
MSYS2 UCRT64 shell, installs it into a staging directory and packs
`ipdbg-VERSION-windows-x86_64.zip`:

- IoView and UartBridge with all DLLs they need: the script follows the DLL
  imports with `objdump`, copies the DLLs from MSYS2 and fails if a DLL is
  found neither there nor in Windows;
- the BusAccess and WaveformGenerator libraries for own programs: DLLs,
  import libraries, headers, relocatable pkg-config files;
- the licenses: `LICENSES/MPL-2.0.txt`, and for the DLLs from MSYS2 the
  license files of their packages and `THIRD-PARTY.txt` with package,
  version and license.

The Python and Octave modules are not in the ZIP: they only work with the
MSYS2 Python or Octave they are built for.

Locally, with the MSYS2 packages listed in the job `windows-zip`:

```sh
sw/packaging/windows/make-zip.sh out
```

Builds of a tag have the plain version in the name, other builds also the
commit, e.g. `ipdbg-0.1.0-g1a2b3c4-windows-x86_64.zip`.
